# 测试与安全修改流程

测试目标不是证明“本地 fixture 和真实雨课堂完全一样”，而是把最容易回归的契约分层固定下来，同时保留一个明确、有限的实站确认环节。

## 默认测试栈

### 1. Node 逻辑回归

`tests/downloader.test.cjs` 与 `tests/quiz.test.cjs` 在 Node VM 中运行真实 `main.js`，模拟 `window`/`unsafeWindow`、存储、锁、网络、计时器、WebSocket 和保存回调。

这层适合验证：

- 雨课堂接口形状、去重键、跨 iframe 事件和跨标签页状态。
- PDF/视频下载调度、HTTP Range、重试、取消、导出顺序和失败保留。
- 答题默认关闭、发题消息、截止时间、AI 超时、随机兜底和防重复提交。
- 用户脚本沙箱与真实页面窗口分离时的边界。

优点是毫秒级、可注入失败和可精确控制时间；缺点是 DOM 与浏览器实际行为被部分替身化。

### 2. 无头浏览器端到端回归

`tests/browser.test.cjs` 启动临时 Edge/Chrome，加载 `tests/browser-fixture.html` 和真实 `main.js`。fixture 不请求雨课堂服务器、AI 服务或真实文件：

- 顶部页面和两层同源 iframe 模拟课堂页面结构。
- userscript loader 使用独立 sandbox `window`，把真实页面作为 `unsafeWindow`。
- `fetch`、WebSocket、媒体元素和 `window.request.post` 是可观察的本地替身。
- `GM_xmlhttpRequest` 返回固定图片/视频，`GM_download` 等待测试主动成功或失败。
- 二维码登录层、SPA 路由、重复注入和 320 像素移动端宽度均可复现。

这层验证真实浏览器中的注入时机、DOM/CSS、iframe 通信、点击链路和异步队列，不验证真实账号认证、网络协议是否已经变化或文件是否真的写入磁盘。

### 3. 实站冒烟测试

实站只用于确认本地替身无法覆盖的边界。建议使用测试账号，或至少先关闭答题，仅检查只读采集和小文件下载。

1. 完整覆盖安装当前 `main.js`，确认标题版本正确，只启用一个版本。
2. 打开雨课堂课程页，确认面板自动出现，二维码/登录页时隐藏。
3. 进入一个课件页和一段短录播，确认顶层各出现一项资源，iframe 内没有重复面板。
4. 只选一个最小资源，模拟或真实网络成功时确认文件保存；不要用批量下载作为首次验证。
5. 刷新页面，确认待下载列表、勾选状态和已保存计数符合预期。
6. 检查控制台是否出现 `[Rainclassroom]` 未处理的异常；记录页面路由、版本和错误文本。

答题只建议在本地 fixture 或明确的测试课堂验证。实站确认时保持答题关闭，避免把协议回归测试变成真实提交。

## 修改 `main.js` 的流程

1. 先运行 `npm test`，确认当前基线全部通过。
2. 为要修改的行为先增加一个最小测试。逻辑分支放 Node 测试；真实 iframe、DOM、事件或用户点击问题放浏览器测试。
3. 确认新测试因原问题失败，而不是因 fixture 本身报错失败。
4. 只修改 `main.js` 中对应路径，运行单层测试快速迭代。
5. 最后运行完整 `npm test`，再做一次实站冒烟测试。

如果线上问题无法在现有 fixture 复现，先把最小协议样本加入 fixture。HAR 样本应删掉 Cookie、Authorization、签名 URL 参数、账号标识和课堂令牌；只保留字段结构、消息顺序和脱敏后的 ID。测试不得重放真实写请求。

## 环境与产物

- 完整自动测试需要 Node.js 22+ 和 Edge/Chrome。
- 浏览器测试使用新临时 profile，不复用日常登录或扩展配置。
- 可用 `RC_BROWSER_PATH` 指定浏览器路径。
- `npm run fixture` 只启动本地手动测试页，不启动真实雨课堂或外网服务。
- 本地通过不能替代真实 Tampermonkey 权限、PDF/MP4 编码、磁盘落盘和线上协议漂移检查。
